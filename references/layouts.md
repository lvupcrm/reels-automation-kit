# 컷 레이아웃 6종 — 컷마다 고른다

**한 영상이 하나의 레이아웃으로 끝나지 않는다.** 해외 레퍼런스 88편을 보면 한 편 안에서
인물 풀 → 상하분할 → 자료 풀 → 타이포로 계속 갈아탄다. 컷시트를 짤 때 **컷마다 아래에서 하나를 고른다.**

> 음성 방식(원음 토킹 / 나레이션 / 무음)은 영상 전체에 **하나로 고정**된다. 레이아웃만 컷마다 바뀐다.

| | 레이아웃 | 언제 |
|---|---|---|
| **L1** | 인물 풀 | 화자가 말하는 구간. 표정이 메시지일 때 |
| **L2** | 실사 풀 | 현장·제품·동작을 보여줄 때 |
| **L3** | 자료 풀 | 기사·앱·문서를 크게 읽힐 때 |
| **L4** | **상하 분할** | 자료를 보여주면서 화자도 살릴 때 — 설명형·사례형의 주력 |
| **L5** | **삽입(PIP)** | 본 화면 위에 참고 화면을 얹을 때 |
| **L6** | 타이포 단독 | 한 문장을 못박을 때. 전환 호흡으로도 쓴다 |

---

## L1 — 인물 풀
화자가 화면을 채운다. 가장 단순하고, 말이 곧 내용일 때 쓴다.
```bash
scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920
```
- 가로 소스는 인물 중심으로: `crop=608:1080:X:0,scale=1080:1920`
- 한 컷이 8초를 넘으면 지루해진다 — 줌을 조금 주거나 다른 레이아웃으로 끊는다.

## L2 — 실사 풀
현장·제품·동작. 나레이션형의 기본 화면이다.
```bash
scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920
```
- HDR 소스는 공통 규약의 톤매핑을 먼저 적용한다.
- 정적인 화면이면 천천히 확대해 움직임을 만든다: `scale=1300:-1,crop=1080:1920:110:(ih-1920)*(t/D)`

## L3 — 자료 풀
기사·앱 화면·문서를 화면 가득. **읽혀야 하므로 팬은 느리게.**
```bash
# 세로로 긴 캡처를 위에서 아래로 훑기 (D = 컷 길이 초)
scale=1600:-1,crop=1080:1920:260:(ih-1920)*(t/D)
```
- 앱 화면은 목업에 넣으면 신뢰도가 올라간다 → `scripts/make_mockup.py`
- 짚어야 할 곳이 있으면 주석을 얹는다 → `scripts/make_annot.py`

## L4 — 상하 분할 ⭐
**설명형·사례형·리액션의 주력 레이아웃.** 위는 자료, 아래는 화자.
"자료를 보여주면서 사람도 살아 있게" 만드는 유일한 방법이다.

```bash
ffmpeg -y -i 자료.mp4 -i 화자.mp4 -filter_complex "\
[0:v]crop=1080:1200:0:(ih-1200)/3,setsar=1[top];\
[1:v]crop=1080:720:0:(ih-720)/3,setsar=1[bot];\
[top][bot]vstack=inputs=2[v]" -map "[v]" out.mp4
```
- 비율은 **자료 1200 + 화자 720**(화자 37%)이 기본. 자료를 더 키우려면 1340 + 580(30%).
- ⚠️ **화자 크롭 y값이 관건이다.** `(ih-720)/2`(중앙)로 두면 얼굴 위가 잘린다.
  `/3`으로 올리거나, 프레임을 뽑아 눈으로 확인하고 조정한다. **한 번은 반드시 확인할 것.**
- `vstack`은 폭이 같아야 한다 — 둘 다 1080으로 맞춘 뒤 합친다.
- `setsar=1`을 빼면 화면비가 틀어진다.
- 자료가 정지 이미지면 `-loop 1 -t <길이> -i 자료.png`로 넣는다.

## L5 — 삽입(PIP)
본 화면 위에 참고 화면을 얹는다. 인터뷰에서 언급 대상을 띄우거나, 반응을 보여줄 때.

```bash
# 라운드 마스크를 먼저 만든다 (Pillow)
python - <<'PY'
from PIL import Image, ImageDraw
W,H,R = 560,996,40
m = Image.new("L",(W,H),0); ImageDraw.Draw(m).rounded_rectangle([0,0,W-1,H-1],radius=R,fill=255)
m.save("pipmask.png")
PY

ffmpeg -y -i 배경.mp4 -i 삽입.mp4 -i pipmask.png -filter_complex "\
[0:v]boxblur=18:2,eq=brightness=-0.06,setsar=1[bg];\
[1:v]scale=560:-1,crop=560:996,setsar=1[pv];\
[pv][2:v]alphamerge[pa];\
[bg][pa]overlay=(W-w)/2:380[v]" -map "[v]" out.mp4
```
- **배경을 블러 처리하고 살짝 어둡게** 해야 삽입 화면이 떠 보인다. 안 하면 둘 다 죽는다.
- 마스크 크기와 `scale`·`crop` 값이 정확히 같아야 한다. 다르면 `alphamerge`가 깨진다.
- 라운드가 필요 없으면 마스크 없이 `overlay`만 써도 된다.

## L6 — 타이포 단독
배경 위에 문장만. **결정적 한 줄**을 못박거나, 컷 사이 호흡을 만들 때.
```bash
python make_typo.py overlay "보조 문구" "강조 문구" ov.png
# 배경 위에 얹기
ffmpeg -y -i bg.mp4 -i ov.png -filter_complex "[0:v]eq=brightness=-0.05[b];[b][1:v]overlay=0:0[v]" ...
```
- 배경은 앞 컷을 블러 처리해 이어 쓰거나, 단색·그라디언트를 쓴다.
- **한 화면에 3~7단어.** 문장을 그대로 옮기면 읽히지 않는다.
- 남발하면 슬라이드쇼처럼 보인다 — 한 편에 1~2회.

## 컷시트에 적는 법
컷시트 단계에서 **컷마다 레이아웃을 명시**한다. 그래야 렌더에서 헤매지 않는다.

```
컷1  0.0~3.2s   L6 타이포     "이 릴스, AI가 만들었습니다"
컷2  3.2~7.0s   L1 인물 풀     훅 발화
컷3  7.0~12.5s  L4 상하분할    위: 앱 화면 / 아래: 화자
컷4  12.5~16.0s L3 자료 풀     기사 캡처 + 화살표 주석
컷5  16.0~20.0s L2 실사 풀     현장 스케치
컷6  20.0~26.0s L4 상하분할    위: 완료 화면 / 아래: 화자
컷7  26.0~30.0s L6 타이포     CTA "댓글에 자동화"
```

## 고를 때의 기준
- **자료가 있으면 L4를 기본으로** 둔다. 88편에서 가장 많이 쓰인 배치다.
- 같은 레이아웃을 3컷 이상 연속으로 쓰지 않는다. 지루해진다.
- L6는 시작·끝·핵심 문장에만. 중간에 자주 넣으면 흐름이 끊긴다.
- 소재가 하나뿐이면 L1/L2만으로도 성립한다 — **없는 자료를 만들려 하지 말 것.**
