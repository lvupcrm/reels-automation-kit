# P1 — 나레이션 몽타주형

주제 하나를 받아 **대본 → 클론 보이스 나레이션 → 자막 → 몽타주 합성**. 입력 영상은 B-roll 소재로 쓰이고, 나레이션이 뼈대다.

**적용 조건**: 주제가 주어졌고(또는 영상에 말소리가 없고 전달할 메시지가 있고), 클론 보이스로 설명하는 형식이 맞을 때.

## 1. 대본 (Claude가 직접 작성)
- 맥락 로드: 작업 폴더의 `PROFILE.md`(있으면) — 업종·타깃·말투·금기.
- 구조: 후킹 질문(1인칭 공감) → 근거 → 약속 + 명확한 CTA. 총 25~35초(3청크).
- 금기: 과장·공포 소구·미검증 수치. TTS용으로 숫자는 한글 표기("오 분에서 십 분").
- 발음이 모호한 단어("읽습니다"↔"있습니다")는 대본 단계에서 명확한 표현으로 바꿔둔다 — TTS가 틀리는 지점이다.

## 1-b. 목소리 레퍼런스가 없다면 — PC 마이크로 바로 녹음 (권장)
폰으로 녹음해 옮기는 것보다 빠르고, **대본 불일치(클론 실패 1위 원인)를 원천 차단**한다.
핵심은 **내가 대본을 먼저 주고 사용자가 그대로 읽게 하는 것** — 그러면 ref_text가 자동으로 정확히 일치한다.

**macOS**
```bash
# ① 마이크 확인 (첫 실행 시 마이크 권한 팝업 → 허용)
ffmpeg -f avfoundation -list_devices true -i "" 2>&1 | grep -i audio
# ② 30초 녹음 (":0" = 기본 입력 장치)
ffmpeg -y -f avfoundation -i ":0" -t 30 -ac 1 -ar 24000 raw_ref.wav
```

**Windows** (장치를 이름으로 지정해야 한다 — 목록에서 정확한 이름을 복사해 쓸 것)
```bat
:: ① 입력 장치 이름 확인
ffmpeg -list_devices true -f dshow -i dummy
:: ② 30초 녹음 (따옴표 안은 위에서 확인한 실제 장치 이름)
ffmpeg -y -f dshow -i audio="마이크 배열(Realtek(R) Audio)" -t 30 -ac 1 -ar 24000 raw_ref.wav
```
1. 사용자 톤(`PROFILE.md`)에 맞는 **3문장·약 18초 대본**을 만들어 화면에 띄우고, "준비되면 시작이라고 말해달라"고 안내한다.
2. "시작" 신호를 받으면 녹음을 **백그라운드로** 걸고 즉시 "🔴 녹음 중"이라고 알린다.
3. 녹음이 끝나면 whisper로 전사해 **실제 발화와 대본을 대조**한다.
   - 앞뒤에 침묵·잡담("이거 된 거예요?")이 붙는 게 정상이다 → 세그먼트 타임스탬프로 **대본 구간만 트림**한다.
   - 사용자가 대본을 살짝 바꿔 읽었으면 **들린 그대로**를 ref_text로 쓴다.
4. 음량을 정규화한다: `loudnorm=I=-16:TP=-1.5` (녹음이 작게 잡히는 경우가 많다).
5. 트림 결과를 다시 전사해 **대본 3문장만 남았는지 검증**한 뒤 작업 폴더에 등록한다:
   `voice/ref.wav`로 저장 + `voice/voice.json` = `{"ref_audio": "ref.wav", "ref_text": "들린 그대로의 문장"}`.
   스크립트(`tts_chunks.py`)에 적지 않는다 — 스킬 폴더는 업데이트로 덮여 목소리 등록이 사라진다.

## 2. 나레이션 (scripts/tts_chunks.py)
- 대본 청크를 한 줄씩 `chunks.txt`에 적고 작업 폴더(`reel_<슬러그>/`)에서 `tts_chunks.py --chunks chunks.txt` → 목소리는 `voice/voice.json`을 자동으로 찾는다 → CPU fp32로 청크별 생성(각 `max_new_tokens=300`) → 0.35초 간격으로 concat → `reel_narration.wav`
- **검증 필수**: 청크마다 재전사해 대본과 대조한다(합본을 한 번에 전사하면 뒤로 갈수록 1~2.7초 밀린다 — `word_subs.py words 청크…`가 청크별로 전사한다). 불일치(옹알이·동음이의 오독)면 해당 청크만 재생성.
- **음색·다이내믹 검수**: `python voice_tools.py qa <레퍼런스.wav> chunk*.wav` — 다른 사람처럼 들리는 청크(음색 거리 6 초과)와 먹히는 청크(피크 낮음)를 재생성한다.
- **문장 첫머리 이물음**("오타이핑"·"요로컬"): 재생성해도 같은 자리에 붙는다 → 문장 앞에 `그리고`·`그런데`·`일단`·`요즘` 같은 ㄱ/ㅇ 접속어를 붙여 흡수시킨다(`craft-notes.md` §3).
- **톤 업 후처리**(레퍼런스 녹음이 차분해 나레이션에 힘이 없을 때): `atempo=1.08,treble=g=2.5:f=3500,loudnorm=I=-15:TP=-1.5`
  적용하면 자막 타임스탬프·컷 길이를 모두 ×1/1.08로 재계산해야 한다.
  **근본 해결**은 사용자에게 밝은 톤으로 15~20초 재녹음을 받아 레퍼런스를 교체하는 것(전사 정확 일치 필수).

## 3. 자막 + 타임라인 (scripts/make_subs.py)
- **자막 줄바꿈은 글자수 그룹핑 금지** — 대본을 **구 단위 문구 리스트**(각 ≤16자, 의미 단위로 미리 쪼갬)로 `phrases.txt`에 정의하고 `make_subs.py reel_narration.wav phrases.txt`로 whisper 단어 타임스탬프에 정렬해 타이밍을 부여한다.
- 산출: `reel_subs.ass`(하단 자막) + `reel_lines.json`(줄별 타임스탬프 — 컷시트·B-roll 배치 기준) + `_fonts/`(합성 시 `fontsdir=_fonts`).
- 배속한 나레이션은 whisper가 끝을 놓친다 → `word_subs.py words 청크_배속.wav … -o words.json` 후 `make_subs.py 나레이션.wav phrases.txt --words words.json`.
- 단어별 배치·키워드 팝 자막을 원하면 `word_subs.py ass`(프리셋 C 문법)를 쓴다.

## 4. B-roll 컷시트 (Claude가 reel_lines.json 기반 작성)
- 줄별 타임스탬프에 키워드를 매칭해 삽입 소스를 제안한다: 사용자 보유 영상·사진, 화면 캡처, 타이포 카드.
- 컷시트는 작업 폴더에 md로 저장한다. 실제 B-roll 오버레이는 ffmpeg `overlay`로 (첫 편은 배경만도 충분하다).

## 5. 몽타주 합성 — 사용자 실사 영상이 뼈대, 화면·타이포 카드는 중간 삽입
영상 파일 경로만 받으면 내용을 훑어보고(프레임 피크) 비트에 배치한다. 가로(16:9) 소스는 `crop=608:1080:X:0,scale=1080:1920`으로 인물·화면 중심 크롭.
컷 소스 3종을 나레이션 비트(`reel_lines.json`)에 맞춰 7~8컷으로 구성:
1. **화면 팬**: 화면 캡처 이미지를 `scale=1600:-1,crop=1080:1920:260:(ih-1920)*(t/D)`로 천천히 훑기
2. **실사 클립**: 사용자 보유 영상(세로 우선) 트림 + `-an` 음소거. HDR 소스는 공통 규약의 톤매핑 체인 적용
3. **텍스트 강조 컷**: `scripts/make_typo.py overlay "보조 문구" "강조 문구" ov.png` → 클립에 `overlay=0:0` + 배경 `eq=brightness=-0.05`
   (스타일 정본은 공통 규약 참조. 그라디언트 단색 카드·`drawtext` 직접 사용 금지)
- 화면 라운드 카드 삽입(자막 위 배경): 캡처 → Pillow 라운드 카드(960px, 그림자, 1080x1920 투명 PNG) → 해당 나레이션 구간에 `overlay=0:0:enable='between(t,a,b)'`로 순차 표시.
- 타이틀은 인트로 3.2초만 + 커버 프레임 추출 (공통 규약 참조).

```bash
# 배경 그라디언트가 필요할 때 (색은 사용자 브랜드 색으로 교체)
ffmpeg -y -f lavfi -i "gradients=s=1080x1920:c0=0x004EDC:c1=0x002A76:x0=540:y0=0:x1=540:y1=1920:n=2" -frames:v 1 bg.png
# 컷들 concat 후 자막·나레이션 합성 (-af apad + -t <영상길이> = 늘어짐 방지)
ffmpeg -y -i montage.mp4 -i reel_narration.wav -vf "ass=reel_subs.ass:fontsdir=_fonts" -af apad \
  -c:v libx264 -crf 18 -preset slow -pix_fmt yuv420p -c:a aac -b:a 128k -t <영상길이> reel_final.mp4
```
(QA 반복은 `-crf 21`로 빠르게, 최종은 단일 패스 마스터 렌더 — 공통 규약 참조)

## 6. 검증된 나레이션 장치 4종 (선택 — 반응이 가장 컸던 편에서 쓴 것)
- **타이포 팝 2단**: 7자 내외 문구를 2단으로 — 네이비(35,45,92)+흰 테두리 14 → 무지개 그라디언트+흰 테두리, 단마다 pop 효과음.
- **스티커 스웜 → 디밍**: 주제에 맞는 스티커(AI 생성·초록 키잉) 4→8→13개로 늘린 뒤 **부정·소멸 나레이션에 맞춰 어둡게**(채도 .25·밝기 .45).
- **터미널 인서트**: 작업 과정을 9단계로 한 줄씩 드러내는 패널이 왼쪽에서 0.4초 슬라이드 인, 끝나면 오른쪽으로 아웃. "지금 보시는 이 릴스도 이렇게 만들었다" 같은 **메타 증거**와 짝이 좋다.
- **CTA 빨간 박스**: "댓글에 [아무 말이나] 남겨주시면"에서 대괄호 부분만 빨간 박스로 — ASS 줄 대신 PNG 카드 + ding.
- 이 장치를 쓴 편의 확정값: 나레이션 1.3배 + treble 2.5/3500 + loudnorm −15 · 자막 Pretendard 88 · 효과음 총 6회. 5비트 대본(결론 선제시 훅 → 공감 문제 → 멈춤 → 해법+인서트 → CTA).
