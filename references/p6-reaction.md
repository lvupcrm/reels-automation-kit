# P6 — 리액션형

**남의 콘텐츠(원본)를 보면서 내 반응을 얹는다.** 소스가 둘이고 음성도 둘이 섞이는 유일한 프리셋이다.

**적용 조건**: 입력에 **원본 콘텐츠**(남의 릴스·경기 장면·시술 영상·화면 캡처)와 **내 반응 영상**(카메라 보고 말함)이 둘 다 있을 때. 사용자가 "이거 보고 리뷰/반응"이라고 말하면 확정.

> ⚠️ **저작권 먼저 확인한다.** 남의 콘텐츠를 쓰는 구조라, 렌더 전에 사용자에게 한 번 묻는다 —
> "원본 영상 사용 권한이 있으신가요? 분석·비평 맥락이면 출처 표기를 넣는 게 안전합니다."
> 출처 표기는 상단에 작은 텍스트로(워터마크 금지 규약의 예외 — 남의 콘텐츠 출처는 표기가 원칙).

## 1. 구조 — 대본이 아니라 반응 포인트

리액션형은 **대본이 없다.** 원본을 보고 실제로 반응한 육성이 콘텐츠다. 대신 **반응 포인트**를 설계한다.

1. 원본을 훑어 **반응할 순간 2~4개**를 고른다 (놀랄 곳·짚을 곳·반박할 곳)
2. 사용자에게 확인: "이 지점들에서 반응하시면 됩니다 — 원본 몇 초 보여주고 → 반응 → 다시 원본"
3. 반응 촬영은 원본을 실제로 보면서. **연기한 반응은 표가 난다.**

레퍼런스 실측(7편): 컷당 중앙값 **13초** — 전 유형 중 가장 느리다. 원본을 충분히 보여주고 반응도 끊지 않는다.
컷은 반응 포인트에서만 나눈다. 잘게 썰면 리액션의 맛(같이 보는 느낌)이 죽는다.

## 2. 화면 — L4 상하분할이 기본

```
┌─────────────┐
│   원본 콘텐츠   │  위 1200px — 주인공은 원본
├─────────────┤
│   내 반응      │  아래 720px — 표정이 살아야 한다
└─────────────┘
```
- 합성 패턴은 `layouts.md`의 L4 그대로. **반응 얼굴 크롭 y값 확인 필수**(중앙으로 두면 이마가 잘린다).
- 원본이 화면 캡처·문서면 L5(PIP)로 뒤집어도 된다 — 원본을 크게, 내 반응을 작게 얹기.
- 결정적 반응 순간은 **반응만 풀스크린(L1)으로 2~3초** 키우면 강조가 된다.

## 3. 음성 — 원본과 반응의 믹스 (이 프리셋만의 규약)

"음성은 전체에 하나" 규칙의 유일한 예외다. 두 오디오를 섞되 **내 목소리가 항상 위**에 있어야 한다.

**정석 — 자동 덕킹**: 내가 말하는 동안 원본 소리가 자동으로 내려간다.
```bash
ffmpeg -y -i 원본.mp4 -i 반응.mp4 -filter_complex "\
[1:a]asplit=2[sc][mix];\
[0:a][sc]sidechaincompress=threshold=0.05:ratio=10:attack=15:release=400[duck];\
[duck][mix]amix=inputs=2:duration=first:normalize=0[a]" \
-map "[a]" ... 
```
- `normalize=0` 필수 — 빼면 두 소리가 다 작아진다.
- 간단 대안: 원본을 상시 `volume=0.25`로 깔고 반응을 그대로 얹기. 원본 소리가 중요하지 않을 때.
- 원본 소리가 아예 불필요하면(문서·화면 캡처) 원본은 `-an`, 반응 원음만 쓴다 — 그냥 P2와 같아진다.

## 4. 자막 — 반응 발화만 전사한다

⚠️ **원본 오디오는 전사하지 않는다.** 음악·환호가 섞인 소리를 whisper에 넣으면 환각(같은 글자 반복)이 난다 — 12번 레퍼런스 분석에서 실제 발생.
- 자막은 **반응 영상의 오디오만** 추출해 `make_subs.py`로 싱크한다.
- 원본 쪽에 자막이 필요하면(외국어 등) 구간을 지정해 수동으로 넣는다.

## 5. 마무리

- 훅: 원본의 가장 자극적인 순간을 **맨 앞에 3초 미리보기**로 당겨온다 ("이게 말이 돼?") → 처음부터 재생.
- CTA: 리액션은 팔로우 유도가 표준 ("이런 분석 계속 보려면 팔로우").
- QA·마스터 렌더는 공통 규약. **오디오 믹스 확인 항목 추가**: 반응 목소리가 원본에 묻히는 구간이 없는지 귀로 확인.
