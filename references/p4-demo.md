# P4 — 앱 데모 튜토리얼형

화면 녹화/캡처가 주인공이고, **클론 나레이션이 기능을 설명**한다. 제품·서비스의 기능 소개·사용법 콘텐츠용.

**적용 조건**: 입력이 화면 녹화이거나, 주제가 "기능 소개·사용법 데모"일 때.

> 💡 용어·개념·도구 설명처럼 **얼굴 없이 화면 카드만으로** 갈 편은 **제작 프리셋 D(`preset-screen-only.md`)** — 카드 좌표(980x1010·자막 y1450)와 프레임 직접 합성 렌더가 정리돼 있다.

## 1. 대본 (Claude가 직접 작성)
- 구조: 훅(문제 상황 1인칭) → 화면 데모 2~3스텝("이렇게 하면") → 결과("이게 됩니다") → CTA. 총 25~40초.
- 각 스텝은 화면에서 보여줄 동작과 1:1 대응 — 대본 문장마다 "무슨 화면·무슨 동작"을 컷시트에 병기한다.
- 맥락·금기는 P1 대본과 동일(`PROFILE.md`·숫자 한글 표기).

## 2. 화면 소스
- **사용자 제공 화면 녹화**: fps·해상도를 확인해 1080 기준으로 통일한다.
- ⚠️ **실계정 화면이면 개인정보 노출 구간을 반드시 확인**한다. 고객 이름·연락처·결제 정보가 스치기만 해도 그대로 공개된다.
  원칙은 **데모 계정·더미 데이터로 재캡처**. 불가능하면 사후 모자이크보다 **녹화 전에 민감 요소를 CSS 블러하거나 촬영 범위에서 빼는** 쪽이 확실하다.
  실제 로그인 화면에서 조작하더라도 **전송·제출·결제 버튼은 누르지 않는다**.
- 웹 화면은 정지 캡처보다 **프레임 단위 스크롤 녹화**가 살아 있다. 시연용으로 새로 꾸민 화면에는 "화면 재구성" 라벨을 단다.
- 자사 웹 대시보드를 소재로 쓸 땐 페이지 전체가 아니라 **필요한 카드 요소만** 2배 해상도(`zoom=2` + 뷰포트 2배)로 찍는다.
- 정적 화면은 스크린샷을 팬하는 편이 녹화보다 깔끔하다(손떨림·마우스 궤적 없음).

## 3. 나레이션
- P1의 TTS 하네스를 그대로 쓴다: `tts_chunks.py` → whisper 재전사 검증 → (필요시) 톤 업 후처리와 타임스탬프 ×1/1.08 재계산. `p1-narration.md` §2 참조.

## 4. 화면 연출
- **라운드 카드**: Pillow로 라운드 카드(960px, 그림자, 1080x1920 투명 PNG)를 만들어 브랜드 색 배경 위에 올린다 — 정적 화면·비포애프터에 적합.
- **풀블리드 팬**: `scale=1600:-1,crop=1080:1920:260:(ih-1920)*(t/D)` — 긴 화면을 훑을 때 적합.
- **클릭 포인트 줌인**: 동작을 강조할 구간은 해당 좌표 중심으로 `crop` 확대 1.15~1.3배 + 필요하면 Pillow로 원·화살표 표시 투명 PNG를 overlay.
  스텝 전환마다 줌 인·아웃을 반복하면 산만해진다 — 핵심 1~2곳만.
- 화면 컷 사이에 실사 클립(사용자 반응·현장) 1~2컷을 섞으면 리듬이 산다(선택).

## 5. 합성
- 자막(`make_subs.py` 구 단위)·타이틀 인트로 3.2초·커버 프레임·마스터 렌더는 모두 공통 규약.
- 화면 속 텍스트와 하단 자막이 겹치지 않게 — 라운드 카드는 화면 상단~중단에 배치하고 자막 `MarginV 560`을 확보한다.
